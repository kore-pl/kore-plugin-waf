# kore-plugin-waf — Плагин WAF

## Что он делает

Плагин управления WAF (**L1.5+ · независим от движка + реальный nft-уровень данных**) с двумя
раздельными обязанностями: **уровень движков** только обнаруживает уже установленные на хосте
WAF-движки (modsecurity / naxsi / coraza / crowdsec), подсчитывает правила и разбирает журналы
блокировок; **уровень данных** реализован самим kore с помощью `nft` (наборы блокировки, ограничение
частоты SYN-сканирования, лимит параллельных соединений на IP), с переключением observe/enforce и
тремя уровнями защиты (свободный/стандартный/строгий с 0.5.0). Этот репозиторий **не содержит ни одного
WAF-движка** и **никогда не выполняет nft в процессе плагина**: все записи идут через канал root-action
из ADR-0018 (ADR-0022 фиксирует форму команд).

- Протокол: `kore.plugin.v1`, `lifecycle=lazy`, уровень глубины `basic`; разрешения `system:read` + `system:admin`.
- Привилегии: объявляет `requires_root: true` и 12 `root_actions` (все — инструкции nft, `irreversible:false`, все обратимые).
- Тег сценария: `sec`; бюджет ресурсов 6 МиБ / 15% CPU / 16 pids.

## Поверхность методов (10 бизнес-методов)

| Метод | Вход | Результат |
| --- | --- | --- |
| `waf.status` | `{}` | Движок: доступность / версия / правила / режим; уровень; состояние `backend` |
| `waf.rules` | `{engine?}` | Наборы правил движка + правила nft-цепочки уровня данных |
| `waf.logs` | `{limit?, since?, rule_id?, engine?}` | Записи журнала блокировок и статистика |
| `waf.toggle` | `{mode, level?, confirm?}` | Переключение observe/enforce/off с уровнем; проверка чтением после записи |
| `waf.ban` | `{ip, ttl_s?, reason?}` | Идемпотентная блокировка (v4/v6, `ttl_s=0` навсегда, 60–2592000) |
| `waf.unban` | `{ip}` | Разблокировка (отсутствие в наборе тоже считается успехом) |
| `waf.bans` | `{limit?}` | Список блокировок с оставшимся временем |
| `waf.rule.add` / `remove` / `toggle` | см. README | Контролируемый список совпадений, сверка `nft -j list`, откат при расхождении |
| `waf.config.get` / `set` | `{}` / `{values}` | Конфигурация 0600, действует со следующего вызова |

Принимаются и `waf.<метод>`, и «голый» `<метод>`; `waf.blockLog` — совместимый псевдоним `waf.logs`.
`name` допускает только строчные буквы / цифры / `-` / `_` (1-32), а `expr` — только совпадения из
списка (`ip saddr`, `ip6 saddr`, `tcp dport`, `udp dport`, `ct state`, `tcp flags syn`); объекты
параметров декодируются строго, опечатка в поле возвращает `E_INVALID`.

## Обнаружение движков и подсчёт правил

`engine=auto` берёт первое совпадение в порядке modsecurity → naxsi → coraza → crowdsec; каждый движок
возвращает доказательства `probed[]` и никогда не выдаёт пустой результат за «нет движка». При явном
выборе движка и существующих настроенных `rules_dirs` / `log_paths` объявленные пути используются.
modsecurity / coraza считают строки директив `SecRule` (включая с отступом, без комментариев и
SecAction), naxsi считает `MainRule` + `BasicRule`, crowdsec считает один сценарий как `rule_count=1`.
`enabled` означает лишь, что файл лежит в активном каталоге с корректными правилами, а не подтверждённую
цепочку include.

## Журналы блокировок

Читается только хвост (по умолчанию 1 МиБ, настраивается 64 КиБ–8 МиБ), разбираются журналы ошибок
ModSecurity / разделы аудита, Naxsi `NAXSI_FMT` / `NAXSI_EXLOG` и JSON-строки. `action` принимает
`blocked` / `detected`; если ID правила получить нельзя, он остаётся пустым, а не угадывается. `since`
поддерживает `1h` / `30m` / `7d` / RFC3339 / `YYYY-MM-DD`; неразбираемые записи при `since` отбрасываются
и учитываются в `skipped_unparsed`; `limit` по умолчанию 50, максимум 200. Нечитаемый журнал возвращает
`E_NEED_ROOT` + подсказку, а не пустой список, выдающий «нет блокировок»; формат crowdsec в этой версии
не разбирается и возвращает `E_UNSUPPORTED`.

## Уровень данных: реальные правила nft

kore создаёт `table inet kore_waf` в своём пространстве имён и не трогает `filter` / `nat` хоста:
два набора блокировки (`banned4` / `banned6`, с CIDR и timeout) и базовая цепочка на input. Четыре
базовых правила (enforce): сброс по наборам (v4/v6), ограничение SYN-сканирования (60/с, всплеск 120)
и лимит параллельных соединений на IP 200; observe использует те же правила с вердиктом `counter log`.
Уровни меняют покрытие внутри одного режима: `loose` 2 правила, `standard` 4 (по умолчанию), `strict` 6
(добавляются сброс некорректных соединений и ограничение перебора SSH). Уровень и режим выводятся чтением
цепочки — **без новых root-action**; смена режима без `level` сохраняет текущий уровень, а `off` очищает
цепочку, поэтому уровень сбрасывается в ноль, а повторное включение использует standard.

Поток (`waf.toggle`): параметры/подтверждение → доступность nft и канала → короткий путь при совпадении
режима и уровня → инициализация при необходимости → применение правил → проверка чтением (режим, уровень
и число правил должны совпадать для `applied=true`). Все действия имеют `irreversible:false`: `enforce`
можно вернуть в `observe`/`off`, а блокировки снять. `modsec-set-mode` из 0.2.0 (`sed -i` в файле режима)
удалён — произвольная запись файлов означает произвольную мощь записи и не аудируется.

## Контракт конфигурации

Сохраняется в `<KORE_STATE_DIR>/config.json` (0600, атомарная запись), приоритет **config.json >
переменные окружения > значения по умолчанию**, объединение по полям, действует со следующего вызова
(`restart_required=false`). Поля: `engine` (auto), `rules_dirs` ([]), `log_paths` ([]),
`mode_config_path` (""), `max_log_bytes` (1048576). Переменные: `KORE_WAF_ENGINE` /
`KORE_WAF_RULES_DIRS` / `KORE_WAF_LOG_PATHS` / `KORE_WAF_MODE_CONFIG` / `KORE_WAF_MAX_LOG_BYTES` ;
историческая `KORE_WAF_RULES_ROOT` отображается на каталоги правил.

## Деградация и честные границы

Без движка уровень движков возвращает `E_UNSUPPORTED` + подсказку по установке, а уровень данных работает;
без `nft` — `backend.available=false`; с nft, но без root-канала — `E_NEED_ROOT`; при расхождении чтения —
`applied=false` + причина. Явно заявленные непроверенные пункты: на тестовом хосте нет работающего
WAF-движка; бэкенд `ipset` не реализован и удалён из таблицы форм ядра; сквозной прогон под настоящим
root- kored не завершён (пути отказа проверены, пути успеха покрыты root-интеграционными тестами ядра);
проверен только nft 1.1.6; журналы observe попадают в журналы ядра и здесь не разбираются.

## Установка и проверка

```sh
gofmt -l . && GOWORK=off go vet ./... && GOWORK=off go test -timeout 200s ./...
make build && make dist
```

`make dist` детерминирован (фиксированные записи, нормализованные mtime/owner/mode, `gzip -9n`),
две сборки дают одинаковый sha256. Артефакты releases: `dist/waf-<версия>.tar.gz` + `.sha256`.
